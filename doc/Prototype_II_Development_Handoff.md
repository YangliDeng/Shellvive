# Shellvive Prototype II：开发交接提示词

以下内容可以直接交给负责 Godot 开发的 AI 或开发者执行。

## 开发任务

请在现有项目 D:\Godot\Project\shellvive 中，以增量修改方式接入 Prototype II 的手绘素材与流程。项目使用 Godot 4.6、GDScript、1280×720 视口及 GL Compatibility 渲染器。

Shellvive 是大学课程的 2D 横向卷轴生存游戏，对应 SDG 14：Life Below Water。玩家控制海龟，吃水母恢复生存值，躲避造成伤害或减速的塑料。箱子提供卡牌选择。

先阅读现有脚本、场景和下列素材说明，再修改。工作区已有用户尚未提交的修改；保留这些修改，按现状接入，不重置或整体替换项目文件。

本轮已完成素材处理和预览。接下来需要完成的是场景、动画资源、生成位置及玩法逻辑的接入。

## 二、已经确定的视觉要求

1. 海龟保留两张原画泳姿。绿色动态外圈已经有可用序列图和预览；优先提供该效果，同时保留 Inspector 开关，可切换无外圈或静态外圈，供最终审美确认。动态外圈序列图已经包含海龟身体，不要再叠一层重复身体。
2. 活鲨使用静态图，通过位置移动完成游动与冲刺。发现提示是独立 AnimatedSprite2D，在预警期间循环显示，冲刺开始时隐藏。
3. 海水与海床图片已经旋转完成，在引擎里直接使用最终PNG。所有环境层使用同一套缩放、定位与视口映射。
4. 后期死鲨必须腹部朝上，整条鲨鱼和渔网完整位于下方沙地区域，周围背景为沙地。最终版本不是卡在海水与沙地交界处，也不是半截埋在交界处。
5. seabed_hard.png 已经包含死鲨。使用它时，不重复添加一个常驻死鲨节点。单独的 dead_shark.png 可以用于过场，过场节点结束后清理。
6. 设备箱摆在海床上。需要半埋效果时，用局部前景沙遮住箱体底部约10–20%。这条遮挡要求适用于设备箱；保留死鲨已经确定的完整沙地摆放效果。
7. 红色危险排线、黄色箱子提示笔触和绿色海龟外圈均为视觉效果，碰撞范围按实体身体设置。
8. 设备箱的黄色笔触独立轻微抖动，贴着箱体的笔画根部固定。箱体本身不漂移、不缩放，卡牌图案和黑色轮廓保持原画。

## 三、Prototype II 的玩法顺序

### 0–45秒：开场与鲨鱼冲刺

- 沿用现有水母教学、生存值恢复、塑料伤害及减速逻辑。
- 前45秒出现2–3次虎鲨，当前12、24、36秒的生成设置可以作为起点。
- 预警开始时，只记录一次海龟的当前深度，并锁定冲刺通道。
- 在该深度显示横向阴影预警约1秒，同时播放四帧感叹号循环。玩家可游到通道上方或下方躲避。
- 冲刺沿锁定通道水平通过；预警后的冲刺不持续追踪海龟，不使用追踪转向攻击。
- 两次出现之间逐渐增加可见塑料，但保留清楚的移动空间。

### 约45秒：网缠鲨鱼与阶段过渡

- 停止新增活鲨，并妥善结束正在进行的攻击，避免过场与可伤害玩家的活鲨重叠。
- 使用已有网缠鲨鱼素材表现短暂漂入、下沉或淡入淡出。通过整体位移完成过场，保持静态活鲨的正式素材方案。
- 过场期间海龟继续移动，游戏不因这段叙事暂停。
- 过场结束后切换或平滑过渡到 seabed_hard.png，以沙地上的腹部朝上尸体作为后期阶段的视觉标记。
- 死鲨与海床属于背景，不造成碰撞伤害，不被 Cleanup 卡清除。
- 阶段时间使用游戏内生存计时；卡牌选择暂停时，阶段计时与动画遵循同一暂停状态。

### 45秒后：污染加重

- 沿用现有无尽阶段的塑料生成节奏，并逐渐提高压力。
- 加入横向漂浮的宽渔网，留下明确、足够海龟游过的空隙。可见绳索与碰撞区域一致。
- 接触网时短暂受困或减速，随后释放；同一片网不能每帧重置计时，造成永久困住。
- 受困时间、冷却、缝隙大小及网的生成间隔作为可调参数。
- 水母继续引导玩家跨越不同深度。
- Cleanup 清除漂浮垃圾及设计为可清理的网，打开通路；保留海床背景尸体。
- 目前没有单独的漂浮宽网手绘素材。先用清楚的代码网格占位，并保留可替换贴图字段；不要把带死鲨的整张图片作为可碰撞网障碍。

## 四、箱子与卡牌

- 设备箱优先使用 box_marking_animation.tres 的 marking_loop 动画；box.png 保留为静态备选。
- 动画帧已经包含完整箱体，直接作为箱子视图使用，避免与静态箱体重复叠加。
- 每帧仍为634×568。现有 _fit_box() 按纹理宽度计算缩放；接入图集或 AnimatedSprite2D 时改用单帧宽634，而不是整张图集宽2536，并沿用现有 body_rect、地面锚点和 SandCover 设置。
- 箱子生成在海床高度，而不是水域中央。继续从右侧进入，并与海床采用一致的世界滚动关系。
- 以箱体黑色底边对齐地面。PNG下方的黄色提示笔触占据额外高度，不应把整张PNG的最底边当作实体箱子的底边。
- 将海床高度、箱子落点偏移、箱子显示尺寸及沙地遮挡量暴露为 Inspector 参数。
- 海龟游到底部时必须能接触箱子的触发区，避免水域边界先夹住玩家而无法拾取。
- 沙地遮挡可用靠近箱子的局部条带实现，避免整张前景沙覆盖已经合成的海床尸体。
- 沿用现有 Rescue、Cleanup 两种卡和三格库存、替换及使用逻辑。
- 选择卡牌时暂停世界，并保持选择UI可操作；关闭选择后恢复游戏。
- 沿用生存值归零、Game Over、重新开始等现有流程。

## 五、当前代码的接入点与差异

请以实际读到的最新代码为准，以下是交接时确认的结构：

- scripts/game.gd：已有45秒开场、鲨鱼生成时间、塑料生成、卡牌暂停与库存联动。_spawn_box() 目前使用水域中央的 spawn_y，需要改成海床锚点。
- scripts/game.gd：get_water_rect() 和 _clamp_y() 负责角色及生成区域。接入新海床后，要统一海床表面、水域下界、海龟边距和箱子触发区。
- scripts/turtle.gd 与 scenes/turtle.tscn：仍使用旧海龟图。换成新的 SpriteFrames，保留输入、速度、塑料叠加和边界逻辑。
- scripts/turtle.gd：_update_appearance() 目前受影响后切换旧 ChokedSprite。接入后继续显示新手绘海龟，可用轻量颜色或附着物提示减速，保持已有叠加与 Rescue 行为。
- scripts/shark.gd：目前是持续追踪海龟并转向的攻击，需要调整为固定深度的预警与直线冲刺。
- scenes/shark.tscn：已经使用新静态鲨鱼和感叹号图，但 alert 动画目前为4fps、非循环。改成约6.667fps，并在预警期间循环。
- scripts/box.gd 与 scenes/box.tscn：已有 Area2D、opened 信号和横向移动。更新贴图、锚点及碰撞范围，保留信号连接。
- scripts/background.gd 与 scenes/Game.tscn：已有 Parallax2D 镜像滚动。接入海水与海床分层；海水可以慢速视差，箱子与海床使用一致的世界速度。
- 新背景原始宽高比与1280×720视口不同。两张环境层必须使用同一缩放与偏移，并根据最终画面确定海床高度，避免海床、箱子和水域限制错位。
- scenes/Game.tscn 中可见部分数值导出项被保存成 null。检查这些覆盖，让有效数值或脚本默认值正常生效。
- 新增渔网脚本或场景时，与现有安全移除、卡牌消耗、暂停和重启接口一致。

## 六、验收要求

- 新素材路径有效，Godot导入、脚本解析和主场景启动无错误。
- 海龟朝右游动；原画、静态外圈和动态外圈可通过明确设置切换；碰撞不包含装饰外圈。
- 活鲨默认使用静态图；感叹号只在预警期间循环。
- 鲨鱼冲刺通道在预警开始后固定，玩家改变深度时通道不追随。
- 约45秒的叙事过渡不冻结海龟移动；后期海床正确显示。
- 后期尸体腹部朝上，完整在沙地区域，不能回到海水交界处；不重复叠加尸体。
- 海底箱子可被海龟实际触碰，卡牌选择、暂停、恢复和三格库存正常。
- 网的安全缺口可实际通过，受困会结束，Cleanup 的移除对象正确。
- 调整视口大小后，海床、水域、箱子与角色位置仍一致。
- 进行至少60秒的实际运行检查，覆盖开场、卡牌选择、鲨鱼冲刺及后期阶段；重新开始后阶段、计时和卡牌状态正确重置。
- 最后说明修改文件、验证结果，以及海床位置、箱子位置、角色大小和难度参数在 Inspector 中的调整方法。
